AI 赋能的 Design to Code 工作流实验。

Bewater Design Studio 正在验证一条更短的路径：让设计师借助 AI，把设计意图转成可复用的前端代码。你可以用它修复视觉问题、制作主题或搭建 UI，再由开发接入正式产品。

打开已安装的 Studio
01 · FIX

修视觉问题

从测试链接复现问题，调整 View、Token 或组件样式。

02 · THEME

制作产品主题

通过语义 Token 创建并检查 Light、Dark 和品牌主题。

03 · BUILD

搭建 UI 功能

设计师完成可复用 View，开发接入真实数据和产品能力。

清晰分工，放心修改

设计师负责 View 和体验质量；开发负责 API、权限、埋点与发布。你做的界面可以直接进入后续开发，而不是停留在一次性 Demo。

完成三步，就可以开始使用。

按顺序完成：下载并解压项目、运行启动命令、发送 Hello 确认连接。第一次设置完成后，以后只需运行 pnpm designer。

下载 Workbuddy ↗
01

下载并解压项目

先将项目包下载到本地，并解压到一个新的空文件夹，再让 Workbuddy 打开它。不要覆盖旧版本，也不要直接上传压缩包或单个文件。

下载项目包到本地 ↗
02

启动 Studio

在 web 文件夹打开 Terminal，复制并运行下面三条命令。

Terminal 
corepack enable
pnpm designer:setup
pnpm designer
03

发送一条 Hello

把测试指令发给 Workbuddy。收到预期回复，说明项目与规则都已连接。

发送给 Workbuddy 
你好，Bewater Design Studio。
请先读取 DESIGNER_START_HERE.md，
然后只回复：“Studio 已连接，可以开始。”

预期回复：Studio 已连接，可以开始。

看到权限错误？ 跳过 corepack enable，改为运行 corepack pnpm designer:setup 和 corepack pnpm designer。

第一次先让 Workbuddy 学规则，不要马上改代码。

看到这些回答，就说明它理解了

SAFE

不会碰真实服务

明确不修改 service、认证、权限、计费和环境配置。

REUSE

STATES

品牌表达

制作一个新皮肤

创建 Token 覆盖层，同时检查组件的各种状态和主题。

请创建 themes/designer-[主题名].css，只覆盖需要变化的语义 Token，不要在页面散落硬编码颜色。把主题加入 Bewater Design Studio 的切换器，并检查默认、悬停、焦点、禁用、错误、Light、Dark 和长内容状态。不要修改标有 “Don't update by hand” 的生成文件。
完整功能

搭建一个设置页面

参考现有示例，交付可以由开发直接接入真实数据的 View。

请参考 designer/features/settings/，新增 designer/features/[功能名]/。拆成 View、interface、mock-data 和 test-ids。View 不得导入 service；数据通过 Props 输入，操作通过 typed callbacks 输出。Mock 覆盖 default、loading、empty、error、long，并在 Bewater Design Studio 中增加入口。复用现有组件和 Token，覆盖响应式、键盘和可访问名称。
测试链接用于定位和验证，不要让 Workbuddy 直接修改部署中的环境。代码改动应该进入独立 Branch 和 PR。
